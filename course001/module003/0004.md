# Proxies — Key Points

## What It Is

- People define "proxy" very differently depending on their role:
  - **Security professionals** think of HTTP proxies (BurpSuite) or pivoting with a SOCKS/SSH proxy (Chisel, ptunnel, sshuttle).
  - **Web developers** think of Cloudflare or ModSecurity used to block malicious traffic.
  - **Average users** think of obfuscating their location to access another country's Netflix catalog.
  - **Law enforcement** often associates proxies with illegal activity.
- Not all of these are correct: a **proxy is a device or service that sits in the middle of a connection and acts as a mediator**.
- **Mediator** is the critical piece: the device in the middle must be able to **inspect the contents of the traffic**. Without that ability, the device is technically a **gateway**, not a proxy.
- The "change my country" use case is usually a **VPN**, which technically is not a proxy — the common misconception is that any IP address change means a proxy.
- Memory aid: proxies will almost always operate at **Layer 7 of the OSI model**.
- Key proxy types: **Dedicated Proxy / Forward Proxy**, **Reverse Proxy**, **Transparent Proxy**.

## Dedicated Proxy / Forward Proxy

- The Forward Proxy is what most people imagine a proxy to be: a client makes a request to a computer, and that computer carries out the request on the client's behalf.
- Typical corporate use: sensitive computers have no direct internet access and must go through a proxy (or web filter) to reach a website.
- This is a powerful line of defense against malware: the malware not only has to bypass the web filter (easy), it must also be **proxy aware** or use a **non-traditional C2** (a way for malware to receive tasking information).
- If an organization only uses Firefox, proxy-aware malware becomes improbable.
- **Internet Explorer, Edge, and Chrome** all obey the "System Proxy" settings by default.
- Malware using **WinSock** (native Windows API) will likely be proxy aware without any additional code.
- **Firefox does not use WinSock** — it uses **libcurl**, so the same code works on any OS. Malware would need to specifically look for Firefox and pull its proxy settings, which it is highly unlikely to do.
- Alternatively, malware could use **DNS as a C2 mechanism**, but if the organization monitors DNS (easily done with **Sysmon**), that traffic should be caught quickly.
- **Burp Suite** is another Forward Proxy example — most people use it to forward HTTP requests, but it is the "swiss army knife" of HTTP proxies and can also be configured as a reverse or transparent proxy.

## Reverse Proxy

- A reverse proxy is the reverse of a forward proxy: instead of filtering **outgoing** requests, it filters **incoming** ones.
- The most common goal is to listen on an address and forward traffic into a closed-off network.
- Many organizations use **Cloudflare** because its robust network can withstand most **DDoS attacks**, and it lets them filter the amount and type of traffic reaching their webservers.
- **Penetration testers** configure reverse proxies on infected endpoints: the endpoint listens on a port and sends any connecting client back to the attacker through that endpoint.
- This is useful to bypass firewalls or evade logging. If an organization runs an **IDS** watching external web requests and the attacker has SSH access, a reverse proxy can push web requests through the **SSH tunnel** and evade the IDS.
- **ModSecurity** is another common reverse proxy — a **Web Application Firewall (WAF)**.
- WAFs inspect web requests for malicious content and block the request if it is malicious. The [**ModSecurity Core Rule Set**](https://owasp.org/www-project-modsecurity-core-rule-set/) is a recommended starting point for learning more.
- Cloudflare can also act as a WAF, but that requires letting Cloudflare **decrypt HTTPS traffic**, which some organizations do not want.

## (Non-) Transparent Proxy

- All proxy services act either **transparently** or **non-transparently**.
- **Transparent proxy**: the client does not know it exists. It intercepts the client's communication requests to the internet and acts as a substitute instance; to the outside it appears as the communication partner.
- **Non-transparent proxy**: we must be informed about its existence. The user and the software receive a special **proxy configuration** ensuring traffic to the internet is addressed to the proxy first.
- Without that configuration, communication via the proxy is impossible — and since the proxy usually provides the only path to other networks, internet communication is generally cut off entirely.

## Acronyms

- **C2**: Command and Control (malware tasking channel)
- **DDoS**: Distributed Denial of Service
- **DNS**: Domain Name System
- **HTTP / HTTPS**: Hypertext Transfer Protocol (Secure)
- **IDS**: Intrusion Detection System
- **OSI**: Open Systems Interconnection
- **SOCKS**: Socket Secure (proxy protocol)
- **SSH**: Secure Shell
- **VPN**: Virtual Private Network
- **WAF**: Web Application Firewall

## Definitions

- **Proxy**: a device or service sitting in the middle of a connection that acts as a mediator and can inspect the traffic contents.
- **Gateway**: a middle device that cannot inspect/mediate traffic contents — the distinction from a proxy.
- **Forward Proxy**: mediates and filters **outgoing** client requests (e.g. corporate web filter).
- **Reverse Proxy**: mediates and filters **incoming** requests, forwarding them into a closed-off network.
- **Transparent Proxy**: the client is unaware of it; it intercepts requests and substitutes itself as the communication partner.
- **Non-Transparent Proxy**: requires explicit proxy configuration on the client; without it, no communication passes.
- **Proxy aware**: software (or malware) that reads and honors the system's proxy settings instead of connecting directly.
- **WAF (Web Application Firewall)**: inspects web requests for malicious content and blocks them.

## Noteworthy Tools

- **[Burp Suite](https://portswigger.net/burp)**: The "swiss army knife" of HTTP proxies — commonly a forward proxy, but configurable as reverse or transparent.
- **[Chisel](https://github.com/jpillora/chisel)**, **[ptunnel](https://github.com/utoni/ptunnel-ng)**, **[sshuttle](https://github.com/sshuttle/sshuttle)**: SOCKS/SSH proxy tools used for pivoting.
- **[Cloudflare](https://www.cloudflare.com/)**: Reverse proxy with a network robust enough to absorb most DDoS attacks; can also act as a WAF (requires HTTPS decryption).
- **[ModSecurity](https://modsecurity.org/)**: Open source Web Application Firewall operating as a reverse proxy; see the [ModSecurity Core Rule Set](https://owasp.org/www-project-modsecurity-core-rule-set/).
- **[Sysmon](https://learn.microsoft.com/en-us/sysinternals/downloads/sysmon)**: Windows system monitoring that makes DNS monitoring (and thus DNS-based C2 detection) easy.

# Networking Overview — Key Points

## What It Is

- A network enables two or more computers to communicate with each other.
- Networks vary by topology (mesh, tree, star), medium (ethernet, fiber, coax, wireless), and protocol (TCP, UDP, IPX).
- Security professionals must understand networking because network failures are often silent — the error produces no obvious message, so findings get missed.

## Flat Networks vs. Segmentation

- A large, flat network is easy to set up and can be operationally reliable, but it offers almost no defense in depth — like calling a house secure because the door has a lock.
- Splitting one large network into many smaller networks that communicate through controlled paths adds layers of defense.
- Pivoting through a network is not difficult in itself; doing it *quickly and quietly* is hard, so segmentation mainly slows attackers down and makes them noisy.
- Three analogies for segmentation benefits:
  - **Access Control Lists around small networks** = a fence with defined entry/exit points. An attacker can climb it, but that is unusual and therefore easy to detect (e.g. "Why is the printer network talking to the servers over HTTP?").
  - **Mapping and documenting each network's purpose** = lights around the property, making all activity visible (e.g. "Why is the printer network talking to the internet at all?").
  - **Intrusion Detection Systems (Suricata, Snort)** = bushes under the windows: a deterrent against network scanning (e.g. "Why did a port scan originate from the printer network?").
- On a flat /24 network where devices simply pull a DHCP address, applying these restrictions is very hard.

## Subnetting Pitfall (Pentester Story)

- Most networks use a /24 subnet, so many penetration testers set the mask 255.255.255.0 by default without verifying it.
- On a /24, hosts can talk directly as long as the first three octets match (e.g. 192.168.1.xxx).
- Changing the mask to /25 splits that range in half, so a host can only reach systems in "its half."
- Example layout that broke an assessment:
  - Server Gateway: 10.20.0.1/25
  - Domain Controller: 10.20.0.10/25
  - Client Gateway: 10.20.0.129/25
  - Client Workstation: 10.20.0.200/25
  - Pentester IP: 10.20.0.252/24 (gateway set to 10.20.0.1)
- The tester reached client workstations and stole a workstation password via Impacket, but wrongly reported the Domain Controller as offline — it was simply on a different subnet. Misunderstanding the mask kept them off all high-value targets such as database servers.

## How Traffic Flows (Mail Analogy)

- The internet is a collection of many subdivided networks (e.g. a "Home Network" and a "Company Network").
- Networking can be pictured as sending mail: one computer sends a package, another receives it, and an address is required.
- The address typed into the browser is a URL; the host portion of it is the Fully Qualified Domain Name (FQDN).
- Difference between the two:
  - An **FQDN** (`www.hackthebox.eu`) specifies only the "building."
  - A **URL** (`https://www.hackthebox.eu/example?floor=2&office=dev&employee=17`) additionally specifies the "floor," "office," "mailbox," and the "employee" the package is meant for.
- We know the address but not its geographic location — that resolution is done for us:
  - Our **router** is the local post office we use to reach the internet.
  - The router forwards the packet to the main post office, our **Internet Service Provider (ISP)**.
  - The main post office consults the address register / phonebook — **DNS (Domain Name Service)** — which returns the "coordinates," i.e. the **IP address**.
  - The packet is then delivered directly to that location.
- The web server receives the request and sends the website data back through the company network's router to the specified return address (our IP address).

## Network Design: What Should Be Segmented

- The example "Company Network" should ideally consist of **five separate networks**:
- **Web Server → DMZ (Demilitarized Zone)**: clients on the internet can initiate connections to it, so it is more likely to be compromised. Isolating it lets administrators put network protections between the web server and everything else.
- **Workstations → their own network**, ideally with a Host-Based Firewall rule preventing workstation-to-workstation traffic. Workstations sharing a network with servers make spoofing and man-in-the-middle attacks far more dangerous.
- **Switch and Router → an "Administration Network"**: prevents workstations from snooping on device-to-device communication. Without a trusted management network, visible OSPF (Open Shortest Path First) advertisements let anyone on the internal network inject a malicious advertisement and man-in-the-middle any network.
- **IP Phones → their own network**: stops computers from eavesdropping on calls, and — because voice is highly latency-sensitive — lets administrators prioritize that traffic to avoid lag.
- **Printers → their own network**: printers are next to impossible to secure. On Windows, if a printer claims authentication is required during a print job, the client will attempt NTLMv2 authentication, which can lead to stolen credentials. Printers are also excellent persistence footholds and receive large amounts of sensitive information.

## Case Study: The Shipped Printer

- During COVID, a tester bought an expensive printer, exploited it to embed a reverse shell (remote access), and shipped it to a target company with minimal on-site staff.
- A phishing email thanked staff for coming in and framed the printer as a convenience for printing/scanning work to take home.
- The printer was connected almost immediately, and the domain administrator's computer sent it his credentials.
- A well-segmented network would likely have blocked this attack:
  - The printer should not have been able to reach the internet.
  - The workstation should not have been able to talk to the printer over port 445.
  - The printer should not be able to initiate connections to workstations (though printer/scanner combos may legitimately need to reach a mail server to send scanned documents).

## Definitions

- **Flat network**: a single large network segment in which all devices can reach each other directly, with no internal boundaries or filtering.
- **Subnet mask**: the value that defines how much of an IP address identifies the network — e.g. /24 (255.255.255.0) lets all hosts sharing the first three octets talk directly, while /25 splits that range into two halves that cannot talk directly.
- **Pivoting**: moving from one compromised system or network segment to another in order to reach deeper targets.
- **DMZ (Demilitarized Zone)**: an isolated network segment for systems that must be reachable from the internet, kept separate so a compromise there does not expose the internal network.
- **Host-Based Firewall**: firewall rules enforced on an individual machine rather than at a network device, e.g. to block workstation-to-workstation traffic.
- **Man in the middle**: an attack where the attacker positions themselves between two communicating parties to read or alter the traffic.
- **Topologies**: mesh, tree, star, etc.
- **Mediums**: ethernet, fiber, coax, wireless, etc.
- **Protocols**: TCP, UDP, IPX, etc.

## Noteworthy Tools

- **[Suricata](https://suricata.io/)**: Open source network threat detection engine, usable as both IDS and IPS.
- **[Snort](https://www.snort.org/)**: Open source intrusion detection/prevention system based on traffic signatures.
- **[Impacket](https://github.com/fortra/impacket)**: Python collection for working with network protocols — widely used to relay or capture Windows credentials during penetration tests.

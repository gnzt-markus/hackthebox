# Networking Models — Key Points

## What It Is

- Two networking models describe the communication and transfer of data from one host to another: the **ISO/OSI model** and the **TCP/IP model**.
- Both are simplified representations of so-called **layers**, which turn transferred bits into contents readable for us.

## The OSI Model

- The OSI model, often referred to as the **ISO/OSI layer model**, is a **reference model** used to describe and define communication between systems.
- It has **seven individual layers**, each with clearly separated tasks.
- **OSI** stands for **Open Systems Interconnection** model.
- It was published by the **International Telecommunication Union (ITU)** and the **International Organization for Standardization (ISO)** — hence the name ISO/OSI layer model.

## The TCP/IP Model

- **TCP/IP (Transmission Control Protocol / Internet Protocol)** is a **generic term for many network protocols**, not just those two.
- The protocols are responsible for the **switching and transport of data packets** on the internet.
- The internet is entirely based on the TCP/IP protocol family.
- Other members of the family include **ICMP (Internet Control Message Protocol)** and **UDP (User Datagram Protocol)**.
- The protocol family provides the functions needed for transporting and switching data packets in private or public networks.

## ISO/OSI vs. TCP/IP

- **TCP/IP** is a communication protocol allowing hosts to connect to the internet; it refers to the Transmission Control Protocol used in and by applications on the internet.
- In contrast to OSI, TCP/IP **relaxes the rules** that must be followed, as long as general guidelines are respected.
- **OSI** is a communication gateway between the network and end users.
- The OSI model is usually called the **reference model** because it is newer and more widely used, and it is known for its **strict protocol and limitations**.

## Packet Transfers

- In a layered system, devices in a layer exchange data in a specific format called a **protocol data unit (PDU)**.
- Example flow when browsing a website: the remote server software first passes the requested data to the **application layer**; it is then processed layer by layer, each layer performing its assigned functions.
- The data is transferred through the network's **physical layer** until the destination server or device receives it, then routed back up through the layers — each performing its assigned operations — until the receiving software uses the data.
- During transmission, **each layer adds a header** to the PDU coming from the upper layer; the header controls and identifies the packet. This process is called **encapsulation**.
- Header + data together form the PDU for the next layer.
- The process continues down to the Physical Layer (or Network Layer), where the data is transmitted to the receiver.
- The receiver **reverses the process**, unpacking the data at each layer using the header information, until the application finally uses the data. This repeats until all data has been sent and received.

## Why Both Models Matter for Penetration Testers

- With **TCP/IP**, we can quickly understand how the entire connection is established.
- With **ISO/OSI**, we can take a connection apart piece by piece and analyze it in detail.
- This detailed analysis is typical when we can listen to and intercept specific network traffic (covered further in the **Network Traffic Analysis** module).
- Conclusion: familiarize yourself with **both** reference models and internalize them as well as possible.

## Definitions

- **Reference model**: an abstract, layered description of how communication between systems works — the OSI model's role.
- **Protocol Data Unit (PDU)**: the data format exchanged between devices at a given layer; header plus payload becomes the PDU of the next layer.
- **Encapsulation**: the process by which each layer adds its own header to the PDU received from the layer above, in order to control and identify the packet.
- **Decapsulation (reverse process)**: the receiver unpacks the data layer by layer using each header's information until the application can use it.
- **TCP/IP protocol family**: the collective set of protocols (TCP, IP, ICMP, UDP, and others) that transport and switch data packets in private and public networks.

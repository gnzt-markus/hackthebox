# Data Flow Example — Key Points

## What It Is

- A step-by-step walkthrough of what actually happens when a user on a laptop opens a browser and requests `www.example.com` over their home WLAN.
- It follows the client-server model and ties together the previously covered concepts: WLAN association, DHCP, DNS, encapsulation through the OSI/TCP-IP layers, NAT, and decapsulation.

## 1. Accessing the Internet (WLAN Association)

- The laptop first identifies the correct wireless network / SSID.
- If the network uses WPA2/WPA3, the user must supply the correct password or credentials to authenticate.
- Once the connection is established, DHCP takes over the IP configuration.

## 2. Checking Local Network Configuration (DHCP)

- Before any packet leaves the laptop, the operating system checks whether it has a valid IP address for the local network.
- **IP Address Assignment**: If the laptop has no IP, it requests one from the home router's DHCP server. This address is only valid inside the local network.
- **DHCP Acknowledgement**: The DHCP server assigns a private IP (e.g., `192.168.1.10`) plus additional configuration: subnet mask, default gateway, and DNS server.

## 3. DNS Resolution

- **DNS Query**: The laptop sends a query to the DNS server — typically an external one provided by the ISP or a third party such as Google DNS.
- **DNS Response**: The DNS server looks up `www.example.com` and returns its IP address (e.g., `93.184.216.34`).

## 4. Data Encapsulation and Local Network Transmission

- **Application Layer**: The browser creates an HTTP (or HTTPS) request for the webpage.
- **Transport Layer**: The request is wrapped in a TCP segment (web traffic is typically TCP, not UDP), including source and destination ports — HTTP default port 80, HTTPS default port 443.
- **Internet Layer**: The TCP segment is placed into an IP packet. Source IP = the laptop's private IP (`192.168.1.10`), destination IP = the remote server's IP (`93.184.216.34`).
- **Link Layer**: The IP packet is placed into an Ethernet or Wi-Fi frame containing MAC addresses — source MAC is the laptop's network interface, destination MAC is the router's interface.
- Before sending, the laptop checks its ARP table or sends an ARP request to learn the MAC address of the default gateway (the router), then sends the frame to that MAC address.

## 5. Network Address Translation (NAT)

- The router receives the frame and processes the IP packet.
- It replaces the private source IP (`192.168.1.10`) with its own public IP (e.g., `203.0.113.45`) in the packet header — this is NAT.
- The router forwards the packet to the ISP's network, and from there it crosses the internet toward `93.184.216.34`.
- Along the way, many intermediate routers inspect the destination IP and determine the best path to reach that network.

## 6. Server Receives the Request and Responds

- The destination network's firewall (if present) checks whether incoming traffic on port 80 (HTTP) or 443 (HTTPS) is allowed.
- If it passes the firewall rules, the request reaches the server hosting `www.example.com`.
- The web server software (e.g., Apache, Nginx, IIS) processes the request, assembles the webpage (HTML, CSS, images, etc.) and sends it back as a response.
- The response follows the same path in reverse: the server's IP (`93.184.216.34`) is now the source, the home router's public IP (`203.0.113.45`) the destination.
- When the packet reaches the home router, NAT maps it back to the laptop's private IP (`192.168.1.10`).

## 7. Decapsulation and Display

- The laptop strips away the Ethernet/Wi-Fi frame, then the IP header, then the TCP header, until the application layer data is extracted.
- The browser reads the HTML/CSS/JavaScript and renders the webpage.

## Definitions

- **Encapsulation** is the process of wrapping data in successive protocol headers as it moves down the layers — application data becomes a TCP segment, which becomes an IP packet, which becomes an Ethernet/Wi-Fi frame. **Decapsulation** is the reverse: each header is stripped off as the data moves back up the layers on the receiving host.
- **Default gateway** is the router on the local network that traffic is sent to when the destination lies outside the local subnet.
- **ARP table** is a local cache mapping IP addresses to MAC addresses, so a host doesn't have to broadcast an ARP request every time it sends a frame.
- **NAT** lets many devices with private IPs share a single public IP by rewriting the source address in outgoing packets and mapping responses back to the correct internal host.

## Noteworthy Tools

- **[Apache HTTP Server](https://httpd.apache.org/)**: Widely used open source web server software.
- **[Nginx](https://nginx.org/)**: High-performance open source web server and reverse proxy.
- **IIS (Internet Information Services)**: Microsoft's web server, bundled with Windows Server.
- **[Google Public DNS](https://developers.google.com/speed/public-dns)**: Third-party DNS resolver (`8.8.8.8`) as an alternative to the ISP's.

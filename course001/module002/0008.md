# Internet Architecture — Key Points

## What It Is

- Internet Architecture describes how data is organized, transmitted, and managed across networks.
- Different architectural models solve different problems, and real-world networks often combine several models into hybrids.
- Each model involves trade-offs regarding scalability, performance, security, and manageability.

## Peer-to-Peer (P2P) Architecture

- Each node acts as both a client and a server, communicating directly with other nodes without a central server.
- P2P networks can be fully decentralized or partially centralized, where a central server coordinates tasks but does not host data.
- A popular example is torrenting (e.g., BitTorrent), where seeders upload files that others can download from multiple sources simultaneously.
- Advantages: scalability as nodes are added, resilience if a node goes offline, and distributed cost of resources like bandwidth and storage.
- Disadvantages: complex management across nodes, potential reliability issues if peers leave, and security challenges since each node is exposed to vulnerabilities.

## Client-Server Architecture

- Clients send requests and servers respond, with data and applications residing on centralized servers.
- The tier model organizes server roles into layers to improve scalability, manageability, security, and performance.
- Single-Tier: client, server, and database reside on the same machine; rarely used at scale.
- Two-Tier: splits environment into client (presentation layer) and server (data layer), typical in desktop applications; a browser visiting a website is generally not considered two-tier since it interacts with a web server rather than directly with a database.
- Three-Tier: adds an application server between client and database, separating presentation, business logic, and data layers.
- N-Tier: extends beyond three tiers with multiple application servers, offering high scalability and distributed deployment.
- Advantages: centralized control, applicable security policies, and optimized dedicated server performance.
- Disadvantages: single point of failure, high cost and maintenance, and potential network congestion under heavy load.

## Hybrid Architecture

- Combines Client-Server and Peer-to-Peer elements: central servers handle coordination/authentication, while data transfer happens directly between peers.
- Example: video conferencing apps use a central server for login and session management, while video/audio data flows directly between participants.
- Advantages: relieves server workload by letting peers share data, while the central server still manages authentication and directory services.
- Disadvantages: complex implementation combining centralized and distributed components, and a potential single point of failure if the coordinating server fails.

## Cloud Architecture

- Refers to computing infrastructure hosted and managed by third-party providers (e.g., AWS, Azure, Google Cloud), operating on a virtualized client-server model.
- Provides on-demand access to resources like servers, storage, and applications over the internet.
- Five essential characteristics: on-demand self-service, broad network access, resource pooling, rapid elasticity, and measured service.
- Advantages: scalability, reduced cost and maintenance, and flexibility to access services from anywhere.
- Disadvantages: vendor lock-in, security/compliance concerns from relying on a third party, and dependency on stable internet connectivity.

## Software-Defined Architecture (SDN)

- Separates the control plane (traffic decisions) from the data plane (traffic forwarding), centralizing control in a software-based controller.
- Enables programmable network management, letting administrators dynamically adjust policies and routing.
- Advantages: centralized control simplifying management, programmability and automation, and dynamic optimization of traffic flows.
- Disadvantages: vulnerability if the central controller fails, and complex implementation requiring specialized skills and tools.

## Key Comparisons

- P2P: decentralized (or partial), high scalability as peers grow, complex management, typical for file-sharing and blockchain.
- Client-Server: centralized, moderate scalability, easier management, typical for websites and email services.
- Hybrid: partially central, higher scalability than client-server, more complex management, typical for messaging apps and video conferencing.
- Cloud: centralized in provider's infrastructure, high scalability, easier (outsourced) management, typical for cloud storage, SaaS, and PaaS.
- SDN: centralized control plane, high policy-driven scalability, moderate management requiring specialized tools, typical for datacenters and large enterprises.

## Acronyms

- **P2P**: Peer-to-Peer
- **SDN**: Software-Defined Networking
- **SaaS**: Software as a Service
- **PaaS**: Platform as a Service
- **AWS**: Amazon Web Services

## Q&A – Questions and Answers

**Q: What type of architecture allows nodes to act as both client and server?**

**A**: Peer-to-Peer

**Q: What architecture combines elements of both Client-Server and Peer-to-Peer models?**

**A**: Hybrid

**Q: Which cloud service model involves accessing applications over the internet without managing the underlying infrastructure?**

**A**: SaaS

**Q: In which architecture is the control plane separated from the data plane? (Format: two words, one of which is hyphenated)**

**A**: Software-Defined Networking

**Q: Which architecture is known for decentralized data sharing without a central server?**

**A**: Peer-to-Peer

**Q: What model is used by video conferencing apps to combine centralized coordination with peer-to-peer data transfer?**

**A**: Hybrid

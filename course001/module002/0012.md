## Chapter 1 — "Keep me in the Loop" (Interfaces & Local Ports)

### Inspecting Interfaces with `ifconfig -a`

- `ifconfig` configures network interfaces and displays their current status. By default it only shows *active* interfaces; the `-a` flag shows *all* interfaces, including those that are down.
- The Pwnbox has three interfaces: **ens3**, **lo**, and **tun0**.
- `lo` stands out from the others in three ways:
  - A much greater **MTU** (65536) compared to the other interfaces (1500).
  - Its IPv6 address is `::1` and its scopeid is `host` rather than `link`.
  - Its Layer-2 information reads "loop" and "Local Loopback" instead of an Ethernet MAC address.

### The Loopback Address

- The loopback is always tied to the IPv4 address **127.0.0.1** and is used when a device needs to send network data **to itself**.
- Common purposes: testing that an application works as intended before going live on the network, and keeping services hidden from outside users.
- Example: an e-commerce site stores credentials and session cookies in a database. Rather than exposing the database publicly, it is only reachable by the server itself — the website acts as an API between the user and the database, querying its own database on the user's behalf.

### Enumerating Local Ports with `netstat`

- `netstat` displays network connections, routing tables, and interface statistics.
- `netstat -tulnp4` lists all open/listening TCP and UDP ports for IPv4 in **IP:PORT** format, and — if permissions allow — the program responsible for each port.
- Dropping the `-n` option (`netstat -tulp4`) displays the output as **hostname:service** instead: the loopback IP resolves to `localhost`, and the ens3 IP resolves to the Pwnbox hostname.
- A service listening on **0.0.0.0** is listening on **all interfaces**.
- Findings on the Pwnbox: HTTP (port 80) listening on the ens3 IP → that IP is the Pwnbox's **public IP address**, which is how the browser can reach it. VNC (port 5901) is listening on the **loopback** address.

### Port Forwarding

- **VNC** (Virtual Network Computing) is a protocol for remote screen sharing and remote access.
- Since the desktop is reachable through the browser while VNC only listens on loopback, some form of **port forwarding** must redirect HTTP traffic to the VNC service.
- Port forwarding redirects traffic sent to one TCP/UDP port to another — even across different machines. Example: a Windows host forwards its local port 8888 to a NAT'd Linux VM's SSH port 22, acting as an intermediary since the VM has no directly accessible IP.
- The topic itself is beyond the scope of the module, but worth being aware of.

## Chapter 2 — "Having Tuns of Fun" (VPN Tunnel & Target Enumeration)

### The Three Interfaces Summarized

- **lo (Loopback)**: allows the Pwnbox to send network traffic to itself.
- **ens3 (Public IP)**: enables the Pwnbox to communicate with us over the internet.
- **tun0 (Tunnel)**: a VPN interface — lab targets live on a separate private network, so the Pwnbox must establish a secure connection to reach them.

### Confirming the Route

- `ip route get <target ip>` displays the route traffic takes from the Pwnbox to the target.
- Output confirms all target traffic goes `via <gateway> dev tun0` — a VPN tunnel connecting the Pwnbox to the private lab network, letting us interact with lab machines as if they were on the same local network.
- Using a VPN configuration file plus software such as **OpenVPN**, a computer connects to the VPN server which grants access to the network. HTB Academy's VPN can be downloaded for use with your own workstation instead of Pwnbox.

### Reachability with `ping`

- `ping` tests the reachability of a host on a network. It uses **no TCP or UDP ports**, making it a **Layer 3** protocol in OSI terms.
- `ping -c 4 <target ip>` sends four pings. Without a count, Linux pings indefinitely until `Ctrl + C`.
- **ttl** (time-to-live) indicates how many "hops" a packet may take to reach the target — relevant for internet destinations that traverse multiple routers, rarely for local devices.
- **time** indicates network latency (roughly 71 ms per ping in the example).

### Port Scanning with `nmap`

- `nmap` enumerates open ports on a *remote* machine (whereas `netstat` shows open ports on the *local* machine). It is fundamental for any current or aspiring infosec professional.
- `nmap <target IP>` returns the open TCP ports.
- Typical Windows findings: ports **135, 139, 445** are almost always open on a Windows host; **3389** is RDP (Remote Desktop Protocol); **5357** is Microsoft's Web Services for Devices API, used for device discovery on the network.

## Chapter 3 — "Target Acquired" (OPTIONAL: FTP & HTTP by Hand)

### Deeper Scanning

- `nmap -p21,80 -sC -sV <target ip>` — `-sV` determines the version of the program listening on a port, `-sC` runs default scripts for additional information (e.g., how a service is configured).
- The initial `nmap` scan operates at **Layer 4** (is the TCP/UDP port open or closed). Version scans (`-sV`) and default scripts (`-sC`) use protocol-specific **Layer 7** packets.
- Result: FTP has **Anonymous FTP** enabled (anyone can connect, typically with the username `anonymous`). Port 80 returned little info, suggesting some form of **request filtering** is in place.
- **IMPORTANT**: While not illegal, it is considered unethical to use `nmap` (or any port scanner) against a device you do not own or have explicit permission to scan.

### Talking to FTP with `netcat`

- `netcat` (`nc`) makes raw TCP/UDP connections; whatever you type is transmitted to the connected port. Used here instead of an FTP client to better understand how the protocol works. For HTTP, tools like a browser, `curl` or `wget` would normally formulate the protocol data for us.
- `nc <target ip> 21` connects and returns the FTP banner (`220 Microsoft FTP Service`).
- Login sequence: `USER anonymous`, `PASS anything`, then `PASV` for Passive Mode.
- Each command needs `[Ctrl+V][Enter][Enter]` because FTP requires both a return and a new-line character (`\r\n`), while pressing Enter in netcat only sends `\n`.

### FTP's Two Channels

- **Control Channel** — sends FTP commands (`USER`, `PASS`, `LIST`, `RETR`, etc.) on **port 21**.
- **Data Channel** — transfers files and directory listings on a **dynamic port** (varies by Active or Passive mode).
- In passive mode you must reconnect to the server on a second port. The full port number can't be displayed at once due to FTP protocol limitations, so it is split into two numbers (`p1`, `p2` — the last two numbers of the `227 Entering Passive Mode` response).
- **Port formula: `p1 * 256 + p2`** — e.g., `194 * 256 + 40 = 49704`.
- Workflow: open a second terminal, `nc -v <target ip> <dynamic port>` to attach to the data channel, then send `LIST` on the control channel — the directory listing appears in the data-channel terminal.
- Each new transfer requires a **fresh** `PASV` and a new data-channel connection: `PASV` → recalculate port → `nc -v` → `RETR <filename>` on the control channel → file contents appear in the data terminal.

### Talking to HTTP with `netcat`

- The retrieved note revealed that IIS was configured to only allow requests containing a specific header: `User-Agent: Server Administrator`.
- While FTP recognizes commands like `USER`, `PASS`, `PASV`, `LIST` and `RETR`, HTTP uses a system of **requests and responses built from HTTP headers**.
- Manual request via `nc -v <target ip> 80`:
  - `GET /` tells the server "give me the homepage (root directory)". For a login page it would be `GET /login.php`.
  - The `Host` header tells the server which host is being requested (one server can host multiple unique websites).
  - The `User-Agent` header indicates the agent making the request — for a browser, typically its name and version.
- Server response headers: `Content-Type` states what type of data is being returned, `Accept` (Accept-Ranges) what it can receive, and `Server` reveals the web server software (Microsoft IIS).
- With netcat the raw HTML is printed to the terminal instead of being rendered — which is how a flag hidden in an **HTML comment** becomes visible, something a browser would not display.


### Takeaway

- By sending specific packets of data we adhere to the protocol — the "language" — a particular service speaks.
- FTP is syntactically strict (separate data and control channels, mandatory `\r\n`), while HTTP is more forgiving syntactically but can be merciless toward requests that don't match an administrator-defined specification, such as user-agent filtering.

## Command Reference

| Command | Purpose |
| --- | --- |
| `ifconfig -a` | Show all network interfaces, including inactive ones |
| `netstat -tulnp4` | List listening IPv4 TCP/UDP ports as IP:PORT (+ program) |
| `netstat -tulp4` | Same, but resolved as hostname:service |
| `ip route get <target ip>` | Show which route/interface traffic to a target takes |

| `nmap <target ip>` | Enumerate open TCP ports on a remote host |
| `nmap -p21,80 -sC -sV <target ip>` | Scan specific ports with version detection + default scripts |

| `nc -v <target ip> <dynamic port>` | Verbose raw connection (FTP data channel) |

## Definitions

- **Loopback address (127.0.0.1 / ::1)** is the address a device uses to send network traffic to itself; used for testing and for keeping services private to the host.
- **0.0.0.0** as a listening address means the service is bound to *all* interfaces, not a single one.
- **Port forwarding** redirects traffic arriving on one TCP/UDP port to another port, potentially on a different machine.
- **Passive Mode (PASV)** is an FTP mode where the server opens a dynamic port for the data channel and tells the client which one via the `p1 * 256 + p2` encoding.
- **Anonymous FTP** is an FTP configuration allowing anyone to log in, conventionally with the username `anonymous` and any password.

## Noteworthy Tools

- **[Nmap](https://nmap.org/)**: Port scanner and service/version fingerprinting tool — fundamental for infosec work.
- **Netcat (`nc`)**: Utility for raw TCP/UDP connections; lets you speak protocols like FTP and HTTP by hand.
- **`netstat`**: Displays local network connections, routing tables, listening ports, and interface statistics.
- **`ifconfig` / `ip`**: Interface configuration and routing inspection.
- **[OpenVPN](https://openvpn.net/)**: VPN client software used with a config file to connect to the HTB lab network.
- **Parrot OS**: The Linux distribution running on the HTB Pwnbox.
- **`curl` / `wget`**: Command line tools that formulate HTTP requests for you, as an alternative to raw netcat.
